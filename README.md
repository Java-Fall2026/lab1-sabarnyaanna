## Лабораторна робота №6: Розподіл відповідальності між конструктором та Jakarta Validation (з урахуванням Jackson)

Під час десеріалізації JSON/YAML бібліотека **Jackson** викликає конструктор класу (`@JsonCreator`) для створення екземпляра об'єкта *до* того, як запускається `Validator.validate(item)`.
* **Якщо залишити жорсткі `throw new IllegalArgumentException(...)` у конструкторі**, Jackson перерве читання всього файлу на першому ж невалідному записі (кине `ValueInstantiationException`), і ми не зможемо зібрати всі порушення по полях та відкинути лише один проблемний рядок.
* **Що залишено в конструкторі:** лише безпечна нормалізація вхідних значень (`trim()` для рядків із захистом від `null`) та присвоєння полів без викидання винятків.
* **Що віддано Jakarta Validator:** усі бізнес-обмеження та перевірки формату (`@NotBlank`, `@Pattern`, `@Size`, `@Past`, `@Positive`, `@Min`, `@Max` та власна перехресна анотація `@ValidLoanLimit`). Завдяки цьому Jackson успішно створює об'єкт, а `DataLoader` через `Validator` перевіряє всі поля, формує детальний звіт (`LoadResult` із номером запису, назвою поля й повідомленням українською) та відкидає лише невалідні об'єкти.
