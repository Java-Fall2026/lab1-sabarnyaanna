# Банківське кредитування (Варіант №12) — Лабораторна робота №5

## 1. Що відбувається у `TreeSet` / `TreeMap`, коли порядок `Comparator` не узгоджений з `equals`?
Колекції `TreeSet` та `TreeMap` визначають унікальність елементів виключно за результатом роботи `compareTo()` або переданого `Comparator` (якщо порівняння повертає `0`, об'єкти вважаються однаковими), повністю ігноруючи `equals()` та `hashCode()`.
У нашому прикладі (`TreeSet` із компаратором `Comparator.comparingDouble(Borrower::getMonthlyIncome)`) двоє різних позичальників із різними паспортами (`equals == false`), але однаковим доходом `55000.0` дають результат порівняння `0`. Тому другий об'єкт відхиляється як дублікат, що порушує загальний контракт інтерфейсу `Set`.

## 2. Чим `stream()` у `GenericRepository<T>` відрізняється від `getAll()` із захисною копією?
* **`getAll()`** виділяє пам'ять під новий незмінний список (`List.copyOf(storage.values())`) і одразу копіює туди всі елементи репозиторію (eager-підхід, витрати $O(N)$ по пам'яті).
* **`stream()`** повертає лінивий конвеєр (`storage.values().stream()`) без копіювання даних у проміжну колекцію. Операції фільтрації, мапінгу чи обмеження (`limit`, `findFirst`) виконуються поелементно лише під час виклику термінальної операції, що економить пам'ять і дозволяє зупинити обхід раніше. Водночас `Stream` є одноразовим і прив'язаний до базової колекції під час виконання термінальної операції.
