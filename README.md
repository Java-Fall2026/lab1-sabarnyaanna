# Банківське кредитування (Варіант №12) — Лабораторна робота №4

## Результати бенчмарку пошуку (`SearchBenchmark` на 100 000 об'єктів)
Умови тестування: **100 000 об'єктів** `Borrower`, список для лінійного пошуку отримано один раз через `repository.findAll()`, логування вимкнено (`Level.OFF`), 5 000 ітерацій прогріву JVM, медіана з 15 прогонів по 20 000 операцій (час вказано в наносекундах на одну операцію пошуку).

| Сценарій пошуку | `GenericRepository` (`Map`, $O(1)$) | Лінійний пошук у `List` ($O(N)$) |
| :--- | :---: | :---: |
| **Перший елемент** (`AA000000`) | **45.5 ns** | **34.0 ns** |
| **Останній елемент** (`AA099999`) | **37.7 ns** | **1 401 387.0 ns** (~1.40 ms) |
| **Відсутній елемент** (`ZZ999999`) | **8.4 ns** | **1 364 069.5 ns** (~1.36 ms) |

### Висновок
Різниця практично відсутня під час пошуку **першого елемента** (`45.5 ns` проти `34.0 ns`), оскільки `linearSearch` знаходить його одразу на першій ітерації циклу ($1$ порівняння), навіть трохи швидше за обчислення хеш-коду в `Map`. Натомість під час пошуку **останнього** та **відсутнього** елементів різниця величезна (понад **37 000–160 000 разів**), тому що лінійний пошук змушений пройти всі $100\,000$ елементів списку ($O(N)$), тоді як `Map` обчислює хеш ключа та звертається безпосередньо до потрібного кошика за сталий час ($O(1)$).
